# AVault Android 端需求文档

> 版本：0.1（实施需求）  
> 更新：2026-08-02

## 1. 产品定位

AVault Android 是 AVault Windows 桌面端的局域网客户端。它不扫描手机或电脑目录，也不管理影片资料；它只在用户自己的局域网中连接一台已配对的 AVault 电脑，浏览该电脑的媒体库并在手机内播放视频。

## 2. 技术约束

- Kotlin、Jetpack Compose、Material 3。
- AndroidX Media3 / ExoPlayer 负责视频播放。
- 最低版本以现有工程配置为准，主要验收设备为 Android 15。
- 网络使用 HTTPS/HTTP 客户端与服务端 Bearer Token 鉴权；令牌使用 Android Keystore / EncryptedSharedPreferences 安全保存。
- 不读取 SMB 共享、不依赖电脑共享盘符、不缓存完整影片。

## 3. 功能范围

### 3.1 首次连接与配对

1. 未配对时显示连接引导。
2. 用户在电脑端“连接手机”生成二维码。
3. Android 点击扫码连接，申请相机权限并扫描二维码。
4. 解析配对信息后向桌面端发送配对请求。
5. 配对成功后安全保存服务器 ID、最近地址、端口和访问令牌，进入媒体库。
6. 二维码失效、服务不可达、令牌无效或相机权限拒绝时，提供清晰提示与重试入口。

二维码中的一次性数据不可替代长期访问令牌；日志、崩溃信息和界面不得显示长期令牌。

### 3.2 自动重连与离线状态

- 启动时优先使用上次成功地址自动连接。
- 若地址无效，按已保存的服务器 ID 在局域网重新发现服务端；发现成功后更新地址。
- 电脑关闭、不在同一网络或服务不可达时显示离线页，包含“重试”和“重新扫码”。
- 服务端撤销当前设备后，清除本地配对状态并回到配对引导。
- 第一版仅保存一台电脑；替换电脑须先明确确认。

### 3.3 媒体库

- 首页显示桌面端返回的影片数据，支持网格浏览、下拉刷新、分页加载与图片占位。
- 支持搜索番号、标题、演员和标签；支持观看状态、加入时间、发行日期等服务端允许的筛选/排序。
- 可浏览演员影片页和标签影片页。
- 详情页展示封面、标题、发行日期、时长、演员、标签、简介和本地可播放文件版本。
- 演员资料和社交链接仅展示服务端已保存的数据；打开链接时使用 Android 系统默认浏览器。

### 3.4 多版本播放

- 详情页根据服务端返回的文件版本显示：原画、HEVC 原分辨率、720p HEVC。
- 默认选原画；用户可在播放器内切换版本。
- 切换版本时保留尽可能接近的当前播放位置，并重新请求该文件 ID 的 Range 流。
- 播放前使用 Media3 能力检测；设备不支持 HEVC 或当前容器/编码时显示“此设备无法播放”，不尝试启动外部播放器。
- 使用 Media3 / ExoPlayer 提供播放、暂停、拖动、横竖屏、全屏、缓冲状态、错误提示和续播。
- 播放进度定期同步到桌面端，并在暂停、退出和播放结束时立即同步。
- 不下载完整影片到手机；仅允许播放器必要的临时缓存。

## 4. 交互页面

- 启动 / 自动连接页：连接状态、离线状态、重试。
- 扫码配对页：相机预览、权限说明、手动重试。
- 媒体库首页：搜索、筛选、排序、网格列表、下拉刷新。
- 影片详情页：资料、封面、版本选择、播放入口。
- 播放页：Media3 控件、清晰度/版本切换、播放错误。
- 演员影片页与标签影片页。
- 设置页：当前电脑信息、连接状态、重新扫码/取消配对、应用版本。

### 4.1 与桌面端同步的视觉规范

- 默认深色主题：接近黑色的页面底色、深灰内容层次，避免纯白大面积背景。
- 主强调色使用 AVault 紫色；主要操作、选中状态、播放按钮、进度与可点击资料使用同一紫色体系。
- 卡片、详情信息区与筛选控件采用轻微半透明深色面板、圆角和低对比度细边框；不使用厚重描边或高饱和大色块。
- 标题使用清晰的白色层级，辅助信息使用中低对比度灰色；成功状态为绿色、错误/失效状态为红色、排队或提醒为琥珀色。
- 封面优先：媒体库网格延续桌面端横封/竖封比例逻辑；详情页封面保持原图比例并可点开查看。
- 标签、演员、版本与状态均使用紧凑圆角 Badge；可点击的演员和标签保持紫色反馈。
- 详情页结构与桌面端一致：封面/标题与主要操作在上，影片资料、文件版本和播放入口按层级向下排列。
- 手机端不照搬桌面侧栏：使用底部导航或顶部导航承载“媒体库、搜索、设置”等主入口，但图标、字体层级、颜色和控件状态必须与桌面端统一。
- 动效克制：页面切换、卡片按压、加载和播放状态使用短时淡入/缩放反馈，避免影响媒体浏览与单手操作。

手机端优先保证单手操作、封面可读性和播放控制可达性；当屏幕尺寸有限时，优先保留封面、播放和关键资料，次要字段折叠或在详情中展开。

## 5. API 与数据约束

- 所有请求携带设备令牌；401/403 视为未配对或已撤销。
- 视频流只能按服务端返回的文件 ID 请求，不传递本地绝对路径。
- 支持封面与头像 URL 的缓存、加载失败占位和重试。
- API 响应应至少包含影片 ID、资料字段、文件 ID、版本标签、可用状态及安全媒体参数。
- 客户端不负责爬取 JavBus、FC2、gfriends、公开搜索或 DeepSeek；这些均只在桌面端执行。

## 6. 非目标

- 不控制 PotPlayer，不执行桌面端扫描、整理、转码或资料编辑。
- 不提供公网访问、离线下载、投屏、外挂字幕、多电脑切换、云账户或多用户。
- 不保存完整媒体文件，不作为文件共享客户端。

## 7. 验收标准

1. Android 15 真机可扫描桌面端二维码并成功配对。
2. 重启应用后可自动连接原电脑；电脑离线时有明确状态和重试入口。
3. 可浏览媒体库、搜索、打开影片详情、浏览演员和标签页。
4. 可播放服务端提供的 H.264/AAC 基准文件以及 Android 15 支持的 HEVC 版本。
5. 原画、HEVC 原分辨率、720p HEVC 可切换并尽量保留播放位置。
6. 不支持的编码明确提示，不崩溃、不调用外部播放器。
7. 被桌面端撤销后无法继续访问媒体，并回到配对引导。
